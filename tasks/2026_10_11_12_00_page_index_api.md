## Проблема

Для реализации P0-1 (Wikilinks), P0-4 (Autocomplete) и P1-4 (Heading/Block refs) нужен **Page Index API** — единый источник истины о страницах vault: заголовки, алиасы, пути, обновления. Сейчас такого API нет — поиск страниц разбросан по разным эндпоинтам, нет fuzzy search, нет индекса заголовков/блоков.

## Доказательства

- `GET /api/vaults/{slug}/files` возвращает только файлы, не метаданные страниц (заголовки, алиасы, теги)
- Нет эндпоинта для fuzzy search по заголовкам/контенту
- Нет индекса heading/block ID для wikilink heading/block refs
- Wikilink команда в тулбаре требует ручного ввода названия страницы

## Нефункциональные ограничения

- Индекс должен обновляться инкрементально (не full rebuild на каждый запрос)
- Fuzzy search < 100ms на 10k+ заметках
- Поддержка кириллицы, латиницы, смешанных языков
- Индекс должен выдерживать рестарты (персистентность в SQLite)
- Не должен блокировать запись/чтение файлов

## Не входит в задачу

- Реализация fuzzy search алгоритма (используем готовую библиотеку)
- UI picker модалки (отдельная задача P0-4)
- Heading/block index API (отдельная задача P1-4)

## Желаемое поведение

### API Endpoints

```
GET  /api/vaults/{slug}/pages/index           # Полный индекс (пагинированный)
GET  /api/vaults/{slug}/pages/search?q={q}    # Fuzzy search по заголовкам/алиасам
GET  /api/vaults/{slug}/pages/{path}/headings # Headings для конкретной страницы
POST /api/vaults/{slug}/pages/reindex         # Принудительная переиндексация
```

### Схема индекса (SQLite)

```sql
CREATE TABLE page_index (
  vault_slug TEXT NOT NULL,
  path TEXT NOT NULL,           -- относительный путь от vault root
  title TEXT,                   -- первый h1 или имя файла
  aliases TEXT,                 -- JSON array из frontmatter aliases
  tags TEXT,                    -- JSON array из frontmatter tags
  headings TEXT,                -- JSON array: [{level, text, anchor, line}]
  blocks TEXT,                  -- JSON array: [{id, heading, line}]
  content_hash TEXT,            -- для детекта изменений
  updated_at INTEGER,           -- unix timestamp
  PRIMARY KEY (vault_slug, path)
);
CREATE INDEX idx_page_index_search ON page_index(vault_slug, title);
CREATE INDEX idx_page_index_aliases ON page_index(vault_slug, aliases);
CREATE INDEX idx_page_index_updated ON page_index(vault_slug, updated_at);
```

### Инкрементальное обновление

- При `POST /files/content` (save) → обновить только изменённый файл
- При `POST /files/move` → обновить path для файла и всех детей
- При `POST /files/delete` → удалить из индекса
- Фоновый worker для full reindex (опционально, по расписанию)
