## Проблема

Пользователь уже может иметь personal vault в SQLite и на диске, но endpoint `/webdav/` остаётся placeholder. Нельзя подключить vault из Obsidian и проверить реальный write path.

## Доказательства

- `internal/webdav/handler.go` возвращает `501 Not Implemented`.
- Backend не проверяет Basic Auth для WebDAV.
- Изменения файлов не проходят через vault-safe path и git queue.

## Нефункциональные ограничения

- Auth реализует backend приложения.
- WebDAV использует Basic Auth и ту же таблицу `users`, что веб-логин.
- Один vault = одна папка = один git repo = одна git queue.
- Локи лёгкие, file-level advisory, без глобального блокирования vault.
- Не добавлять conflict branches.
- Не добавлять remote sync/backup.
- Не добавлять nginx/Authelia/auth proxy.
- Не делать web editor.

## Не входит в задачу

- Полная WebDAV lock discovery и расширенные свойства.
- Conflict branch/merge UI.
- Remote backup.
- App-passwords.
- Shared vault permissions UI.
- Web editor locks.

## Желаемое поведение

- `/webdav/<vault-slug>/` обслуживает vault текущего Basic Auth пользователя.
- Пользователь может подключить vault из Obsidian по URL `/webdav/<vault-slug>/`.
- Поддержаны MVP-методы: `OPTIONS`, `PROPFIND`, `GET`, `HEAD`, `PUT`, `MKCOL`, `DELETE`, `MOVE`, `LOCK`, `UNLOCK`.
- Запись в файл создаёт родительские директории при необходимости.
- Запись/удаление/перемещение ставят краткий advisory lock или возвращают `423 Locked`, если файл уже залочен другим владельцем.
- После успешной модификации путь попадает в per-vault git queue.
- Basic Auth с неверным паролем возвращает `401`.
- Доступ к чужому vault возвращает `404` или `403` без раскрытия лишней информации.
- Доступ к `.git`, absolute path и path traversal запрещён.

## Заметки по реализации

- Реализовать WebDAV handler поверх существующих `store`, `vault.Service`, `locks.Service`, `git.Client`/queue registry.
- URL shape: `/webdav/<vault-slug>/<path>`.
- `Destination` для `MOVE` принимать только внутри того же `/webdav/<vault-slug>/`.
- `PROPFIND` depth `0`/`1` достаточно для MVP.
- XML response должен быть совместим с базовыми WebDAV clients.
- Для `LOCK` можно хранить lock owner как token-bound owner; для обычных write operations использовать owner `webdav:<user-login>`.
- Git queue debounce берётся из `COMMIT_DEBOUNCE`.

## Критерии приёмки

- WebDAV больше не placeholder.
- `OPTIONS` показывает WebDAV методы.
- `PROPFIND /webdav/<vault>/` возвращает multi-status.
- `PUT` создаёт файл в vault.
- `GET` читает созданный файл.
- `MKCOL`, `DELETE`, `MOVE` работают внутри vault.
- После `PUT` git repo содержит commit или очередь может быть flushed в тесте.
- Smoke test через `./test/run-smoke.sh` проверяет WebDAV Basic Auth и file roundtrip.
- Docker test stack проходит smoke.
