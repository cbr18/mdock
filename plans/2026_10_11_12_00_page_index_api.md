## Последовательность реализации

### Фаза 1: БД и Store (1-2 дня)

1. **Миграция БД** (`internal/store/migrate.go`)
   - Добавить таблицу `page_index` с индексами
   - Миграция выполняется при старте

2. **Store методы** (`internal/store/page_index.go`)
   - `UpsertPageIndex(vaultSlug, path, PageIndex) error`
   - `DeletePageIndex(vaultSlug, path) error`
   - `GetPageIndex(vaultSlug, path) (*PageIndex, error)`
   - `ListPageIndex(vaultSlug, offset, limit) ([]PageIndex, int, error)`
   - `SearchPageIndex(vaultSlug, query string, limit int) ([]PageIndex, error)`
   - `GetPageHeadings(vaultSlug, path) ([]Heading, error)`
   - `ReindexVault(vaultSlug) error`

3. **Модель** (`internal/store/page_index_types.go`)
   - `PageIndex` struct
   - `Heading` struct (level, text, anchor, line)
   - `BlockRef` struct (id, heading, line)

### Фаза 2: Search Engine (2-3 дня)

1. **Выбор движка**: SQLite FTS5 (встроен, без внешних зависимостей)
   - Виртуальная таблица FTS5 на `title, aliases, content`
   - Поддержка prefix search, phrase search
   - Rank by bm25

3. **Store методы поиска**
   - `SearchPageIndex` использует FTS5
   - Поддержка prefix (`query*`), phrase (`"exact phrase"`), fuzzy (Levenshtein через SQLite)

### Фаза 3: API Endpoints (1-2 дня)

1. **Роуты** (`internal/app/routes.go`)
   ```
   GET  /api/vaults/{slug}/pages/index
   GET  /api/vaults/{slug}/pages/search?q={q}&limit={limit}
   GET  /api/vaults/{slug}/pages/{path}/headings
   POST /api/vaults/{slug}/pages/reindex
   ```

2. **Handlers** (`internal/app/page_index.go`)
   - Пагинация (offset/limit)
   - Валидация query параметров
   - Обработка ошибок

### Фаза 4: Интеграция с файловыми операциями (1-2 дня)

1. **Hooks в git queue** (`internal/git/git.go` → `flush`)
   - После успешного commit → `store.UpsertPageIndex` / `DeletePageIndex`
   - Асинхронно, не блокирующий ответ

2. **File operations** (`internal/app/service.go`)
   - `save` → `UpsertPageIndex`
   - `move` → `UpdatePageIndexPath` (oldPath → newPath)
   - `delete` → `DeletePageIndex`
   - `create` → `UpsertPageIndex`

4. **Reindex endpoint** — full rebuild (используется при миграции/восстановлении)

### Фаза 5: Heading/Block Index (1-2 дня)

1. **Парсинг Markdown** для извлечения заголовков и block IDs
   - Использовать существующий `livePreviewExtension.splitBlocks`
   - Извлекать ATX headings, setext headings
   - Находить `^block-id` маркеры

2. **Store методы**
   - `GetPageHeadings(vaultSlug, path) ([]Heading, error)`
   - Хранить в JSON поле `headings` таблицы `page_index`

### Фаза 6: Тесты и документация (1 день)

1. **Unit тесты** (`internal/store/page_index_test.go`)
2. **Integration тесты** (`internal/app/page_index_test.go`)
3. **API документация** (`docs/api-page-index.md`)

## Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| FTS5 не поддерживает fuzzy search нативно | Высокая | Высокая | Использовать trigram extension или Levenshtein в Go |
| Индексация 10k+ заметок медленная | Средняя | Средняя | Инкрементальная, батчами, в фоне |
| Конкурентное обновление индекса | Низкая | Высокая | Транзакции БД, mutex на уровне vault |
| FTS5 не поддерживает кириллицу 잘 | Низкая | Средняя | Токенизатор unicode61 + remove_diacritics |
