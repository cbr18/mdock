# WebDAV MVP для Obsidian

Task: [12_08_2026_20_05_webdav_mvp.md](../tasks/12_08_2026_20_05_webdav_mvp.md)

## Последовательность реализации

1. Расширить `store` методами доступа к vault по slug для пользователя.
2. Передать в server зависимости `vault.Service`, `locks.Service`, `git.Client` и git queue registry.
3. Реализовать WebDAV Basic Auth middleware внутри handler.
4. Реализовать path routing `/webdav/<vault-slug>/<path>`.
5. Реализовать `OPTIONS`, `PROPFIND`, `GET`, `HEAD`.
6. Реализовать modifying methods `PUT`, `MKCOL`, `DELETE`, `MOVE`.
7. Подключить lightweight locks для modifying methods.
8. Подключить enqueue git commit после успешных изменений.
9. Добавить unit tests для handler и smoke test через docker test stack.
10. Обновить README/docs по WebDAV URL.

## Риски

- WebDAV clients отличаются по набору методов и заголовков; MVP может потребовать уточнения после проверки конкретной версии Obsidian.
- `Destination` header в `MOVE` может приходить absolute URL; нужно корректно нормализовать.
- Git queue async, поэтому тесты должны flush или ждать commit аккуратно.
- Lock semantics WebDAV шире, чем MVP advisory locks.

## Заметки по откату

Откатить новый WebDAV handler и server wiring. Vault files/DB/volumes не удалять без отдельного запроса.
